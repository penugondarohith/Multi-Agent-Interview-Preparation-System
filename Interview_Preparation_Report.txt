TECHNICAL INTERVIEWER
=========================================
Technical Interview Guide for MERN Intern at TryLity

**Introduction:**
This technical interview guide is designed to assess the skills and knowledge of a MERN Intern candidate for TryLity. The guide consists of 5 key technical/coding/project questions that range from easy to hard. The expected answers are provided in bullet points for each question.

**Question 1: Easy - React.js Basics**
What is the difference between a controlled component and an uncontrolled component in React.js? Provide an example of each.

* Expected answer:
	+ Controlled component: A component that has its state managed by React, where the state is updated using the setState() method.
	+ Uncontrolled component: A component that has its state managed by the DOM, where the state is updated directly on the DOM element.
	+ Example: A controlled component is a text input field where the value is updated using the setState() method, while an uncontrolled component is a text input field where the value is updated directly on the DOM element using the value attribute.

**Question 2: Medium - Node.js and REST APIs**
Design a simple REST API using Node.js and Express.js to perform CRUD operations on a collection of books. Provide the API endpoints and a brief description of each.

* Expected answer:
	+ API Endpoints:
		- GET /books: Retrieve a list of all books
		- GET /books/:id: Retrieve a book by ID
		- POST /books: Create a new book
		- PUT /books/:id: Update a book by ID
		- DELETE /books/:id: Delete a book by ID
	+ Brief description: Each endpoint performs a specific CRUD operation on the collection of books, using HTTP methods (GET, POST, PUT, DELETE) to interact with the data.

**Question 3: Medium - MongoDB and Database Design**
Design a MongoDB database schema to store user information, including name, email, and password. Provide a sample document and explain the data types used.

* Expected answer:
	+ Database Schema:
		- users collection:
			- _id (ObjectId): unique identifier
			- name (String): user name
			- email (String): user email
			- password (String): user password (hashed)
	+ Sample document:
		- {
			"_id": ObjectId("..."),
			"name": "John Doe",
			"email": "john.doe@example.com",
			"password": "hashed_password"
		}
	+ Data types: ObjectId, String

**Question 4: Hard - React.js and State Management**
Implement a simple todo list app using React.js and Redux, where users can add, remove, and toggle the completion status of todo items. Provide the code for the reducer, actions, and component.

* Expected answer:
	+ Reducer:
		- const initialState = [];
		- const todoReducer = (state = initialState, action) => {
			switch (action.type) {
				case 'ADD_TODO':
					return [...state, { text: action.text, completed: false }];
				case 'REMOVE_TODO':
					return state.filter((todo) => todo.text !== action.text);
				case 'TOGGLE_TODO':
					return state.map((todo) => {
						if (todo.text === action.text) {
							return { ...todo, completed: !todo.completed };
						}
						return todo;
					});
				default:
					return state;
			}
		};
	+ Actions:
		- const addTodo = (text) => ({ type: 'ADD_TODO', text });
		- const removeTodo = (text) => ({ type: 'REMOVE_TODO', text });
		- const toggleTodo = (text) => ({ type: 'TOGGLE_TODO', text });
	+ Component:
		- const TodoList = () => {
			const [todos, dispatch] = useReducer(todoReducer, []);
			const [newTodo, setNewTodo] = useState('');
			const handleAddTodo = () => {
				dispatch(addTodo(newTodo));
				setNewTodo('');
			};
			return (
				<div>
					<input type="text" value={newTodo} onChange={(e) => setNewTodo(e.target.value)} />
					<button onClick={handleAddTodo}>Add Todo</button>
					<ul>
						{todos.map((todo) => (
							<li key={todo.text}>
								<input type="checkbox" checked={todo.completed} onChange={() => dispatch(toggleTodo(todo.text))} />
								<span>{todo.text}</span>
								<button onClick={() => dispatch(removeTodo(todo.text))}>Remove</button>
							</li>
						))}
					</ul>
				</div>
			);
		};

**Question 5: Hard - System Design**
Design a high-level architecture for a real-time chat application using MERN stack, including user authentication, message storage, and real-time messaging. Provide a brief description of each component and how they interact.

* Expected answer:
	+ Components:
		- Client-side: React.js application with user authentication using JWT
		- Server-side: Node.js server with Express.js, using MongoDB for message storage
		- Real-time messaging: WebSockets or Socket.IO for bi-directional communication between client and server
	+ Interaction:
		- Client sends authentication request to server, which verifies credentials and returns a JWT token
		- Client uses JWT token to authenticate and authorize access to chat functionality
		- Client sends messages to server, which stores them in MongoDB
		- Server broadcasts messages to connected clients using WebSockets or Socket.IO
		- Clients receive and display messages in real-time, using React.js to update the UI
